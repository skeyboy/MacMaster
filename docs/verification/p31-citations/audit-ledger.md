## 这张表把四句话说准了

1. **"重跑要换输出目录"这一条本轮按字面做到了，但字面不够**：12 跑有 12 个不同的 `/tmp` 名字，
   跑与跑之间没有盖。之前写在 `release-readiness.md` §1 与 `feature-roadmap.md` §9 的那句
   "同一个 `audit.log` 本轮被就地写了六回"**是错的**——它把"没入库"写成了"被盖掉"，
   机制说反了，同一轮里由同一支笔犯的、和它批评的那种错一模一样的错。真正的损失是
   **6 跑只活在 `/tmp`**，也就是下面第 2 条。
2. **换了名字 ≠ 留了档**：规则要保的是"有信息量的那一读别丢"，而 `/tmp` 在收口时会被清掉，
   所以名字换了、副本照样没了。这份台账是那条规则的补齐版：**读数入库，日志本体不入库**。
3. **第 11 跑（16:37:52，跑在两份文档的诚实性更正之后）与第 9、10 跑逐字同判据**：
   三个总数 892 / 738 / 664、四道硬判据全 0、只提示那两层 0 与 116 一个没动。
   改动只落在标题三行——`# date:`、`# repo:`（`3a6e631-dirty`），以及 `# index:`
   从 **1020 变 1021**：多的那一个跟踪文件正是刚归档进去的 `audit-postcommit.log` 自己。
   **"提交（或归档）换出处、不换判据"因此又实测到一次，而且这一次连"归档这个动作"都算进去了**；
   序数依旧不加，理由写在 `feature-roadmap.md` §9 那一格里。
4. **这份台账自己也是被抽的语料之一**：第 12 跑是给它和两份文档改完之后的复核，三个总数从
   892 / 738 / 664 变成 **893 / 739 / 665**——多的那一条就是上一段末尾那个指向门禁脚本落盘行的锚：
   写它的时候只当是句寻常的行号，它照样被抽走、照样进了判据，而判据跑出来的结果是"对"
   （那一行确实是 `cat "$TMP/report.txt" > "$OUT/audit.log"`）。
   四道硬判据全 0、只提示那两层 0 与 116 一个没动，另外两行标题跟着动：
   `# docs scanned` 36 → 37、`# index:` 1021 → 1022。
   紧接着的复跑一度读到 **894 / 739 / 665**：唯一数一个没动、条次加一，多的那一条正是这一句里
   把同一个锚**重述了一遍**——同一条引用说两遍就多一个个数，抽取器不认"这是在叙述不是在引用"。
   把它改成不带行号的说法之后回到 893，也就是这张表第 12 行那份归档件的数。
   **所以"引用条次"这种数只要文档还在写就没有终值**，这里的写法是拿第 12 跑当这一次提交的读数，
   而两份分析文档里引的那三个数说的是第 9 到第 11 跑那一份语料——两句都不算错，各自指着哪一跑，
   现在都写在格子旁边。
