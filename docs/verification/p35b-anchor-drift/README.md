## 这两份读数罩不住的四类东西

1. **裸 `:NNN` 续列**（`` `MMOptimizer.swift:243` 浏览器、`:265` 系统状态`` 里第二个）。
   两份工具的正则都要求冒号前面紧跟文件名，续列对它们是不可见的。本轮人工补了 22 处分析文档里的续列，
   另有根 README 第 9 行一处（合计 23），清单在 `release-readiness.md` §1 那一格里。
2. **重指之后写进文档的行**：`--write` 落盘后这些行就成了"本轮新写的行"，
   同一份工具第二次跑只会看到 `可重指: 0`。幂等是想要的性质，代价是它复核不了自己。
   复核靠 `git diff docs/` + 上面这份 `--preview`。
3. **基线就错的锚点**（本轮新发现的失败类，最贵的一类）：工具算的是"这一轮改动的位移"，
   引用起点本身错了它照搬——`fidelity-optimizer.md` 那一族删除链锚点（写的是 `MMOptimizer` 第 352-371 行那一段
   与第 583 行，按 §7.7 裸写）、类型名 `BrowserCacheView`）在 HEAD 上就已经指到
   夹具 switch 与 `MMFailurePanel` 上了，全仓也没有 `BrowserCacheView` 这个类型。
   机械重指只会把一个错行号搬到另一个错行号，看起来更像真的。这一族只能靠
   `grep` 现读逐条钉，钉过的落点写在 `fidelity-optimizer.md` §2 与 §0。
4. **`.md` → `.md`：文档顶漂文档**（**这一类 P36 已收，记在这里是因为它正是本族那 11 条的成因**）：
   当时量尺的目标文件集只有"被改过的非测试 `.swift`"，本轮那种"改文档把指向文档行号的引用顶漂"
   整族在扫描面之外，所以那 11 条是手工逐条 +6 重指的。P36 把被改的 `.md` 与 `.sh` 补成第二族目标，
   并把 base 做成第二个参数（`./Scripts/p29-anchor-drift-audit.sh "" HEAD~1` 在提交之后还问得出上一轮），
   过程、受控注入与读数在 `release-readiness.md` §7.26。
