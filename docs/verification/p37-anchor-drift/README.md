## drift-postremap.txt —— **不是新的账**，是量尺的自复性演示

同一把量尺在 `--write` 之后再跑一遍：报 **24 DRIFT + 16 不可自动重锚**，比改写之前**还多**。
它拿「HEAD 第 N 行的原文」与「工作区第 N 行的原文」比，而文档此时指的**正是**工作区那一行，
所以每一条刚重指好的锚点都会被再报成漂。`p29-anchor-remap.py` 的自复性那段说的就是这件事
（"只能在同轮内、提交前跑一次……幂等是想要的性质，但它意味着这工具复核不了自己改过的结果"），
这一份是它第一次被拍成照片。**复核改得对不对只能靠人读**：本轮的手法是把这 6 个被改文件的
全部引用逐条抽出来，连**引用落点那一行的原文**一起打出来对（50 条，逐条判），
那份表没有落盘，判据与结论写在 §7.29。

## 这一族罩不住什么

- 只认**带文件名**的引用；文档里裸写的 `:NNN` 续列（`` `MMOptimizer.swift:243` 浏览器、`:265` 系统状态``
  里第二个那种）对两份工具都不可见，只能人扫。本轮电池那一屏的表里就有 **12 处**这种写法
  （9 处裸 `:NNN`／`:NNN-MMN`，另有 3 处拿方法名打头的 `batteryPercentText:345-348` 那种——
  抽取器要求冒号前是**文件名**，符号名一样看不见），12 处逐条现读对过，全部落点正确。
- 区间只按**起始行**比对，结束行漂了而起始行没漂的看不见；上面那两处 `card()` 区间正是这个形状。
- `FRESH` 那一档**不复核**：它只保证"本轮新写的行不再被搬一次"，不保证那一行里的旧坐标被重量
  （假阴性那一条就是这一档放进来的）。
- 8 条 `UNRESOLVED`（HEAD 那行是空行、或工作区同文本命中过多）工具一律交人工，本轮 8 条逐条读过，
  其中 3 条落在本轮新写的电池行上（它们本来就是对着工作区写的，HEAD 那一版根本没有那一行）。
