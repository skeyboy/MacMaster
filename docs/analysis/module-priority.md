## 开发顺序

| 优先级 | 模块与任务 | 验收标准 | 进度 |
| --- | --- | --- | --- |
| P0 | MMCore 撤回状态；MMCleaner、MMUninstaller、MMDisk、MMOptimizer 删除结果回写 | 成功、失败、受保护拒绝分别可见；失败项仍在列表或标记中；部分撤回可以重试剩余文件 | 已完成，见下方验证 |
| P1 | MMCleaner / MMUninstaller 扫描归属与确认 | 确认与执行共用路径清单；未知大小不计入确定合计；容器和孤儿候选保持谨慎默认值 | 功能已收口，见 [P1 验收](p1-cleaner-uninstaller.md)；真实权限档待复核 |
| P2 | MMDisk / MMMonitor 读数与交互 | 面积、占用和速率有明确口径；首次采样、读取失败、空结果不是同一画面 | 主体已实现，继续多状态设计对照 |
| P3 | MMGuardian / MMOptimizer 诊断与维护 | 只报告可证实的权限与设备状态；维护动作有真实效果或明确标为只读建议 | 主体已实现，设备正分支待实机复核 |
| P4 | 全站设计还原与发布准备 | 各屏 HTML/PNG 与 SwiftUI 的正常、空、加载、失败、权限态对照；浅深色和最小窗口无重叠；所有包测试与 App 构建通过 | 清理页列顺序已按稿对齐，其他屏继续核对 |

优先级按数据损失与错误结论风险排序，不按侧栏顺序排序。设计稿示例数字只作视觉占位，生产页面必须显示本机测量值或明确的未知状态。规划中的 XPC Helper、Widget 和自动更新缺少发布、权限和数据契约，不纳入当前模块主体的完成判定。

## 本轮 P0 验证

- `MMCore`：部分撤回后保留剩余文件的入口，跨重启可继续；最近操作跳过全失败记录。38 项测试通过。
- `MMCleaner`：用户文件夹只按成功记录更新父目录体积与选择；共享行组件按设计稿改为“大小 → 风险 → 操作”。13 项测试通过；[清理页实机夹具图](../verification/mmcleaner/cleaner-column-order.jpg)。
- `MMUninstaller`：本体、孤儿、废纸篓残留的失败项保留；零成功时不弹成功 toast。72 项测试通过。
- `MMDisk`：标记只在成功移走时清除，父目录成功同时清子标记；48 项测试通过（1 项按环境条件跳过）。
- `MMOptimizer`：重复文件只删除成功记录对应的行，失败项留待重试；40 项测试通过。
- 其余 `MMUI`、`MMFileScanner`、`MMMonitor`、`MMGuardian` 分别通过 17 / 46 / 20 / 78 项测试。九个包总计 372 项通过；`MMDisk` 有 1 项按环境条件跳过。Release App 已重新组装。
