# 发版前三项待拍板：许可 / 权利人与年份 / 签名与公证身份

> 这一份是**决策单，不是实现**。三项都由人定，实现不代选（`release-readiness.md` §1 第 136 行那句
> "两个必须由人拍板、实现不代选的事项"是本单的上位约束）。
> 写它的唯一目的：把散在 §2.1、§2.3、§4 里的候选、代价和"定了之后要动哪几行"并成一张表，
> 让人一次选完，而不是来回读 2,500 行。
> 2026-10-08（P28）现读的所有行号与字符串都是当场测的，不是从 §2 抄的。

## 0. 为什么三项要放在一起选

它们共用**同一些对外字符串**，分开选一定会出现分叉：

| 位置 | 现值（2026-10-08 现测） | 哪一项决定它 |
| --- | --- | --- |
| `Scripts/make-app.sh:111`（写进产物 plist 的 `NSHumanReadableCopyright`） | `MacMaster`——**没年份、没权利人** | 第 2 项 |
| `docs/website/index.html:394`（落地页页脚） | `&copy; 2026 MacMaster. All rights reserved.` | 第 2 项（年份与权利人同一个写法） |
| `Sources/MacMaster/SettingsView.swift:281`（关于页那一格） | 「许可 尚未选择许可」 | 第 1 项 |
| `.github/workflows/release.yml:12-13`（那条注释 + Release 页附件的说明） | 「附件档仍是 ad-hoc 签名、未公证」 | 第 3 项 |

页脚那一行已经写着 `© 2026`，而 plist 那一行连权利人都没有——**这不是"还没填完"，是两处对外主张
本来就不一致**：一处已经在主张权利，另一处自认不知道权利是谁。第 2 项定下来之后这两处必须同步。

## 1. 许可证

先记一条会影响选择的既有事实（不是法律意见）：本仓库**参考**过 7 个上游项目，其中
GPL-3.0 三份（Mole / OverSight / lemon-cleaner）、Apache-2.0 **+ Commons Clause** 一份（Pearcleaner）、
MIT 三份（disktree / stats / SwiftFormat）——见 `docs/analysis/reference-repos.md:45-53`。
它们的处置是「**不进版本控制、也不随产物分发**」（同文件 `:71-73`），所以今天没有触发任何一份上游义务。
**这一条只描述现状**：到底有没有哪一段代码是从 GPL 的上游改写来的，只有作者知道，
文档和门禁都测不出来（`./Scripts/p16-citation-audit.sh` 只保证"引用指得到东西"，
`./Scripts/clone-references.sh` 只把那批"命参考仓库"的引用变成能打开的文件，
两者都不判"这段代码是谁写的"）。那一档的**条数每轮都在动**（它是审计脚本每次重算的读数，
现值只看 `release-readiness.md` §1 的位置引用那一格），所以本单不写死它。

| 候选 | 代价 | 定了之后的后果 | 要动的地方 |
| --- | --- | --- | --- |
| A. **不给许可**（保持现状，默认"保留所有权利"） | 零 | 别人 clone 只算"能看到"，不算"能用"；README 与 Release 页都不能写"开源" | 只需把关于页那一格从「尚未选择许可」改成「保留所有权利」，并确认 README 没在自称开源 |
| B. **MIT** | 零；一份文件 | 最宽。任何人都能闭源再分发，包括把你的代码原样卖掉的第三方——对**工具类**应用这通常可接受，但要知情 | 补根目录 `LICENSE`（含权利人+年份，与第 2 项同一主体）；改 `SettingsView.swift:281`；设计稿 `09-settings.html` 的 09d 板**跟着一起改回**（P10 已把稿子改成与实现同口径，就是防这一处分叉） |
| C. **Apache-2.0** | 零；文件长一点 | 同样宽松，多一条专利授权与"修改要标注"；对贡献者更友好 | 同 B |
| D. **GPL-3.0** | 零；但要**重新审上游** | 衍生作品必须以同源许可分发。一旦选这一条，"只读不转发"这个现状就从"省事"变成"必须论证"——因为这一条正好和上游三份 GPL 相邻 | 同 B，外加：`reference-repos.md:71-73` 那条处置要重述为"确认过没有代码来自上游"，并把那批"命参考仓库"的引用逐条抽查一遍（`./Scripts/p16-citation-audit.sh` 每次重算这一档，`./Scripts/clone-references.sh --check` 只读地把它们变成能打开的文件） |
| E. **闭源免费分发** | 零；但**和本仓库的可见性撞车** | 仓库现在是 **private**（2026-10-08 现读 API：`private=true`、fork 0、watcher 0）。"闭源但免费给人用"要先有一个能下载的地方——把仓库或 Release 公开，跟"专有"这一条并存时需要一句对外说明 | 补 `LICENSE` 写"专有"，并把关于页那一格与 README 里"开源"字样的所有位置清干净 |

**这一项里唯一有硬约束的组合**：D（GPL-3.0）与"上游 GPL 项目只读未转发"这个自述同时成立，需要作者
亲自确认"没写过来源于 GPL 的代码"；B/C 不需要这一步。**A/E 不需要**。

## 2. `NSHumanReadableCopyright` 的年份与权利人

| 候选 | 代价 | 后果 |
| --- | --- | --- |
| A. **个人姓名 + 年份**（`© 2026 <姓名>`） | 需要真实姓名——这是三项里唯一一处会把现实身份写进产物的地方 | 与第 3 项联动：若走 Developer ID，证书主体是个人或组织，那一行**应与证书主体一致**，否则"关于页里的权利人"和"Gatekeeper 显示的开发者"是两套名字 |
| B. **公司/组织主体** | 需要有该主体 | 同上，且以后转让、开票、处理侵权都走主体 |
| C. **只写项目名 + 年份**（`© 2026 MacMaster`） | 零 | 法律上"MacMaster"不是权利主体，页脚与 plist 至少**自洽**（现状是页脚这么写、plist 连年份都没有），但仍然是把没有主体的名字当权利人 |
| D. **删掉这一键** | 零 | plist 少一个对外承诺；关于页那一格随之空掉，比"不知道权利是谁"更诚实，但比 A/B 少一层保护姿态 |

年份口径要一次定死：**`2026` 是首发年**，之后每年追加还是写成 `2026-2027`，两种都常见，选定后
`make-app.sh` 那一格与页脚 `index.html:394` 必须同一个规则（现在这两处一个有年份一个没有）。

## 3. 签名与公证身份（§2.1 三选一的展开）

今天可测到的事实：本地产物 `flags=0x2(adhoc)`、`spctl` 结论 `rejected`
（原文在 `docs/verification/p28-package/package.log` 第 6、7 行）；CI 走的是同一条命令链、
同一个 ad-hoc 身份，所以**挂到 Release 页上的那两个附件也是 `rejected`**。

这一条要加一个前提才成立：**仓库现在是 private**（见第 1 项 E 那一行的现读）。
所以今天能点开 Release 页下载附件的只有协作者，"陌生人双击被拒"要等到仓库或 Release
公开之后才成为对外事实——下面第 2、3 行讲的"发给陌生人"都是那一档之后的事，
不影响这一项怎么选，只影响它什么时候开始咬人。

| 候选 | 代价 | 后果 |
| --- | --- | --- |
| 1. **不签名，只发源码**（§2.1 第 1 条） | 零 | README 写清 `./Scripts/make-app.sh`；Release 页不再挂 dmg/zip（或挂上但明说"请自行构建"）。别人第一次打开不会被 Gatekeeper 拦，因为**根本没有下载这一步** |
| 2. **继续 ad-hoc + 现在的 Release** | 零，已经做到了 | 只有"从自己 clone 的树里跑一遍"或"本机装过"的人能用；从浏览器下载那两个附件的人**双击会被拒**。这不算 bug，是 ad-hoc 的定义 |
| 3. **Developer ID + 公证**（§2.1 第 2 条） | Apple Developer Program 99 USD/年；证书与 app-specific password 要进 CI secrets；流程多三步 `notarytool submit` → `staple` → 再打 dmg | 陌生人下载能直接打开。**功能面代价已量过**：`--options runtime` 在本机打断了 §3 那张表里的**零行**，走这条路不用砍功能（限定条件见 §3 末尾三条）。注意换证书之后 §3 那一轮要重跑——旧的那一轮证的是 ad-hoc+runtime，不是 Developer ID+runtime |
| 4. **Mac App Store** | 账号 + **必须沙盒**，当前代码过不去（§3） | 要砍能力，本单不建议在没有功能取舍决定时走这一条 |

选 3 之后要动的地方（一次列全，免得定了之后才发现散在四处）：`Scripts/make-app.sh` 的 `codesign`
那一行换 identity 并加 `--options runtime`；`Scripts/package-app.sh` 在打包前插公证一步，
它的自校验里要多加一条"已 staple"；`.github/workflows/release.yml` 增加证书导入与两个 secret
（**secrets 只写键名，值不进日志**）；`release.yml:12-13` 那句"ad-hoc、未公证"的注释与
`RELEASE-NOTES.md` 里同类措辞同时改掉——那一句现在是对外的承诺，不是内部说明。

## 4. 这三项挡住什么、不挡住什么

**都不挡住"能不能发一个 v1.0.0"**：三项选完或者都不选，`make-app.sh` 与 `package-app.sh`
都产出同样形态的 zip/dmg/SHA256SUMS。它们改的是**外面的人拿到之后能说什么、能做什么**。

**挡住**：① 把这两个附件发给陌生人（第 3 项）；② README/落地页里任何"开源/许可"字样（第 1 项）；
③ 关于页那一格和落地页页脚各自在说什么（第 2 项）。

**别把这一单读成"发版链路已经实测通过"**。本文最后一次现读（2026-10-08，P28 的 CI 那几跑）：
Release 列表还是空的，tag `v1.0.0` 触发的两跑都红过——第一跑红在 workflow 自己的
`PRERELEASE: unbound variable`，第二跑红在第 5 步的九包单测，且不是断言写错了，是两处
**只在别人家的机器上才现形**的缺陷（一条测试把作者的主目录当事实写进断言、
一处表达式让类型检查器超时）。"633 条单测过不过"这一句今天只在作者机上实测过（633/0/1 通过），
在 runner 上还没绿过。所以那一格由 CI 的记录来填，不由本文填；
这三项决策也不该被"CI 还没绿"卡住——它们和 CI 是两件事。

`release-readiness.md` §10 第 4 步那句"人工确认"要等的就是这三格，一格都没选完之前，
那一格的判定不该由实现打勾。
