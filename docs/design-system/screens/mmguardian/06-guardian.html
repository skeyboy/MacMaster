06c · 敏感权限授权（P3.2 新增卡）—— 本机当前的真实形态是"读不到"。 macOS 27 实测：用户级 TCC.db 目录对无「完全磁盘访问」的进程报 ENOENT（被系统隐藏，不是"不存在"）； 系统级 TCC.db 在 open(2) 层报 EPERM、sqlite 报 rc=23 authorization denied（Unix 权限位 o+r 也拦得住， FIFO 与 immutable URI 都绕不开）。两个库都打不开时，这一卡必须停留在 "读不到 · 原因"档——列一个空列表会被读成"没有应用持有权限"，是最危险的假通过； 错误原文（errno / strerror / sqlite 码）逐库展示，动作只有"被带去系统设置"，不写库、不提权。 系统级库存着屏幕录制/辅助功能/键盘监听，即便授予 FDA 后用户级可读，系统级仍可能始终读不到—— 届时是"部分可读"档：列表 + 点名没读到的库（见 06 主屏卡片顶部警示条）。"查到了没有"（可读且 0 行） 与"没查到"（读不到）是两个不同文案，右边第二张卡演示前者。依据与全部实测原文见 docs/analysis/guardian-tcc.md。
