今天有什么 ／ 要什么
1 落点的卷身份没人记
现在：TrashRecord 只有 originalPath/trashPath/size 三格 （FileTrashService.swift:265-277）。落点是 FileManager.trashItem 定的，我们只把 resultingItemURL 抄进台账（:45）。
要：删除时顺手取 volumeUUIDString（本轮现读编译核实这个成员在 SDK 里）写进台账。 必须在删除时取——拔盘之后再问那个路径，resourceValues 直接抛错（档 B 实测）。
2 新字段只能可选
现在：台账读不出来时把坏文件改名成 *.corrupt-<时间戳> 留档，而不是静默覆盖（P1.6 落地记录）。
要：新字段必须可选。写成必填会让用户已有的整份台账解码失败，然后被改名——"撤回"入口连同记录一起没了， 代价比那句假话大得多。缺字段那一档走 E，不猜。
3 不能用"挂载点目录在不在"
现在：谁都没这么判，但这是最容易被写成判据的那一句。
要：不要用。档 B 实测 fileExists(挂载点)=真、目录是空的、它的卷身份已经变成主卷 ⟹ 这一句会把"盘已取下"判成"盘还在"，正好判反。
4 不能复用候选根那一档过滤
现在：VolumeRootProbe.snapshot() 走默认档全量枚举，但它给的行没有 UUID 这一格； VolumeRoots.passesFilter（VolumeRoots.swift:99-104）还要 browsable。
要：这一族直接吃 mountedVolumeURLs(includingResourceValuesForKeys: [.volumeUUIDStringKey], options: []) 的 UUID 集合，不要过 browsable。本轮实测：夹具卷以 -nobrowse 挂上时枚举里就在， 但 browsable=假（档 A 第 11 条），过了那道滤就漏。

现在：MainWindow.swift:676-685 三支，:684 那四个字写死。
