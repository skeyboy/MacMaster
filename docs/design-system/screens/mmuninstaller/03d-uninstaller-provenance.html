第二块：确认面板加一行「来源」+ 一条 brew 提醒。 提醒用警示底而不是普通说明，因为它说的是一件做完之后才会发现的事：账本失同步。文案必须同时讲清 "我们不会替你执行 brew"——这一页的删除动作只有废纸篓一条路径，来源识别不新增任何执行能力。 名字对上但设备号没对上的那一档（CodeEdit）这里换成"来源只是名字对上，未按设备号验证"，并且不给命令： 凭据不足时不推荐一条会改动系统状态的指令。

来源　　无法判定 判定依据：没有 brew 账本、App Store 收据或安装包凭据对得上。"无法判定"不等于"手动安装"——装在别的卷、换了名字、用了别的安装器都会落在这里。 两个 cask 都声明同名时：来源　无法判定（两个 cask 都声明了这个名字：firefox、firefox-beta） 两份 staged 链接抢同一个 bundle 时：来源　无法判定（firefox、firefox-beta 两份账本把同一个 .app 摆到了这里）
第三块：五档来源的文案合同。 这张表是实现与截图的对照基准：没有凭据就是没有凭据，所以最后一档写"无法判定"，绝不写"手动安装"； 两个 token 抢同一个名字时不替用户挑第一个，降级并点名；抢的是同一份文件（设备号 + inode 相同）时， 这句要照实说成"两份账本把同一个 .app 摆到了这里"——两种歧义的可信度不同，文案不能混着一句带过。 行内徽章（列表）只覆盖前两档，后三档只在详情与确认面板里出现。
