03f · 应用卸载 —— 卸载前发现「这个应用正在运行」（P31a）。第一块：列表行 + 详情页。 列表那一格只有"正在运行"占：它会改变你接下来要做的事（先退出，再卸载）。 "未检测到"与"无法判定"都没有这种后果，与 03d 的来源徽章只给 brew 相关是同一条取舍—— 同一行两枚徽章可以并存（来源一枚、运行一枚），互不顶掉。 详情页这一块夹在四张数字卡与「基本信息」之间，三行各有分工：值说结论（带进程号，一个进程就写一个， 多个写「N 个进程（100、200）」），判定依据说这句话凭什么、以及它是只读的， 第三行只在真的对上时才出现，说后果与边界。 颜色分三档（警告 / 说明 / 承认看不出），因为三档说的话不一样。 这一版不代用户退出应用，所以每一句"正在运行"都必须同时带上"移到废纸篓不会让它退出"和 "MacMaster 不会代你退出或结束进程"——只带前半句会让人以为删完就干净了，只带后半句像在暗示按钮会替他做。 画板里 RunningFoo / IdleFoo 是 Scripts/p31-running-fixture.sh 造的假应用， 取证照片（docs/verification/p31-running/）里那一行是它被真的启动之后系统给出的进程号， 不是喂给界面的合成值；夹具因此必须是 Cocoa 应用——不连窗口服务的进程不发启动通知， 第六块那张"界面自己从「未检测到」变成「正在运行」"就拍不出来。 四档的照片覆盖：01 位置对上、03 未检测到、05 只有包名对上、 06 通知驱动的刷新；只有「无法判定」没有照片（本机那种进程不存在），它只有单测。

03f-2 · 第二块：确认面板的提醒，与来源提醒同住一格、互不顶掉。 面板打开的瞬间会重读一次进程快照——面板要说的是按下按钮这一刻的状态，不是列表载入时的旧状态。 提醒只说不拦：「移到废纸篓」按钮仍然是可点的（红色、默认动作）， 因为"正在运行"不改变"这个包可以安全地移走"这件事，只改变"移走之后它还活着"这件事。 如果来源是 brew，那一条 brew 提醒照旧在上面（见 03d 画板 2），两条各说各的后果。 这一档的判据在 RunningAppStatePresentationTests 里钉着： 提醒里不得出现「已退出」「将结束」这类替用户做完的语气。
03f-3 · 四档的文案合同（"正在运行"按证据分两档；实现里 MMUninstaller.swift「运行状态的呈现口径」一节逐字照这张表）。 判据：快照里有没有一条的 bundle 位置或包名与本 bundle 对上（两条都大小写不敏感）。 位置对上 = 这一份文件在跑；只有包名对上 = 那个进程说它在别处——可能是真的另一份 （换过安装目录、App Translocation 的临时副本），也可能只是同一条路径的另一种写法。 这个"我们分不出来"必须在界面上说出来，否则用户会以为"退出那个就好"。

话只能说到"写法不同"，不能说"不是同一个文件"：判定只比路径字符串（见 AppRunningState.resolve 上不解析符号链接的取舍）， 而路径字符串不相等推不出"两个文件"——/tmp 与 /private/tmp 就是同一个文件的两种写法， 第一版实拍当场抓到过这句假话。实物照片：docs/verification/p31-running/05-fixture-identifier-only.png （夹具 Scripts/p31-running-fixture.sh 造了两个同包名、不同位置的 bundle，启动的是 Elsewhere/ 那一份）。 上面那两行的 pid 与夹具根是**当前那张照片里的字面值**：夹具根每次 mktemp，重跑一轮就会变，别把"对不上"当成缺陷。
