03c · 应用卸载 —— 刚拖进废纸篓的提示卡（P1.5）。 卡片插在页头与左右分栏之间，只在停在「已装应用」这一档、且监听器报出了新条目时才出现； 设置里关掉「在应用卸载页提示清理刚拖入应用的残留」后这一页不留任何痕迹（不把设置页的话复述第二遍）。 卡片的存在前提是"本体已经在废纸篓里"，所以这里的动作只有"清理散在 ~/Library 的残留"， 不出现「卸载应用」「移到废纸篓」——删除列表由 report.deletionRoots(for:) 单点给出， 永远不含已在废纸篓的 app 本体（单测锁住这条）。头部图标 tray.and.arrow.down.fill、 徽章 MMBadge("本体已在废纸篓") 用 information 色；正文下方那行是本体绝对路径 · 包标识， 等宽字体、中段截断。残留行与主面板的 ResidualRow 同一套行高与勾选语义： safe 项默认勾选、caution 项默认不勾，root 属主项勾选框直接禁用。 汇总行按实测数字："已选 2 项 · 6.3 MB · 未勾选 2 项"，右侧「全选可删项」只勾可删的， 「清理勾选的残留」是 destructive prominent，未扫描或选中 0 项时置灰。 一次拖进多个应用时，标题左侧换成 menu Picker + "有 N 个应用刚进废纸篓"。

03c-2 · 同一张卡片的三个非"已扫出"档，以及整页读不到废纸篓时的降级横幅。 自上而下：①扫描中（ProgressView + "按包名与容器证据扫残留…"，汇总行写"扫描中…"， 不提前给任何数字）；②尚未扫描（钩子没给 home、或扫描任务还没回来：正文说"还没扫残留"， 汇总行必须写"尚未扫描"而不是"0 项 · 0 字节"——没看过 ≠ 没有，这条是本项目的一致性红线）； ③按当前敏感度没匹配到残留（真扫过、结论是空，才允许说"没有"）。 ④整页横幅是这台机器的默认态：没有完全磁盘访问时 ~/.Trash 的 stat 放行、 open() 直接 EPERM(1)，实测如此，所以首次进入这一页看到的就是它，而不是"废纸篓是空的"。 文案带真实错误码，并明确"重新进入这一页或重启应用才会生效"（TCC 授权在进程启动时读取）。 目录压根不存在（新用户从没删过东西）时走另一条文案："废纸篓目录还不存在"，且不放授权按钮—— 那是两种原因，不能合成一种。
